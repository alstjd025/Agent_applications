# EXP-161: 판정선 1.0 (v0.6-후보3)과 판정선 1.0 + 첫 토큰 마감 판정 (v0.6-후보4) 다시 재기

**날짜**: 2026-11-17 (실행 전 작성)
**질문**: EXP-159·160은 후보 arm이 swe 첫 토큰 budget 11.8 s 설정으로, v0.5 arm이 7 s 설정으로 돌아 비교가 무효였다(정정은 두 기록과 `traps.md`).
모든 arm을 채점과 같은 7 s 설정으로 맞췄을 때, v0.5의 판정선 0.9 → 1.0(후보3)과 여기에 첫 토큰 마감 판정을 더한 것(후보4)이 v0.5보다 나은가.

## 판정 (실행 전에 정함; EXP-159와 같은 규칙, 후보마다 v0.5와 따로)

1. 아홉 지표(모든 도착, admitted, 거절률, 클래스별 admitted·모든 도착)를 지표마다: "평균 차이 > max(문턱, 두 조건 각각의 반복 범위)"이면 "다르다". 문턱은 모든 도착·거절률·클래스별 모든 도착 4점, admitted·클래스별 admitted 1점.
2. 분리 유지 조건: chat 처리 중 인스턴스 평균이 같은 세션 v0.5 + 0.5대 이하, chat이 3대 이상인 시간이 v0.5 + 15점 이하(대시보드 분리 지표, run 전체).
3. 채택: "다르다(나쁨)"가 없고, 모든 도착·거절률·클래스별 모든 도착 중 하나 이상 "다르다(좋음)", 분리 유지 조건 성립. 후보3·4가 둘 다 채택 조건을 만족하면 더 단순한 후보3을 고른다(후보4가 어느 지표에서든 후보3보다 "다르다(좋음)"이면 후보4).
4. 판정 전에 여섯 run의 `run_config.json` `workload_config.slo`가 모두 같은지 대조한다.
5. 같이 적는 것: 받은 swe의 마감 위반 종류(첫 토큰 / 평균 토큰 간격 / 몰림), swe TTFT p99, iteration 시간 분포(인스턴스 종류별), preemption, goodput, chat 거절률, 마지막 구간 갈림 여부.

**예상**: EXP-159에서 본 swe의 첫 토큰 초과(190~215건) 상당 부분은 11.8 s 설정 때문이었을 것이므로, 후보3에서도 줄어든다. swe의 평균 토큰 간격 초과는
deepresearch·swe 인스턴스가 판정선 75 ms에 붙어 돌아서 생긴 것이라 남을 수 있다. 후보4는 첫 토큰 판정이 이제 7 s 기준이라 swe 첫 토큰 초과를 더 줄일 것이다.
