# EXP-133 — 누적 ablation: 우리 것만 순서대로 벗겨 llm-d 쪽으로 수렴시킨다

실행 전에 씀. 2026-09-14 KST.

## 1. 왜 leave-one-out 이 틀린 모양이었나

EXP-131 이 여섯 요소를 하나씩 빼서 **셋이 0 이었다** — 잔액 조건 0, 보류 0, 클래스 선호는
한 시간 trace 에서 1.4~2.2. EXP-132 가 **왜 그렇게 작게 읽히는지를 직접 쟀다**: chat 을 하나도
들지 않은 (인스턴스, 시각) 쌍이 선호를 켜면 **2.1 / 4 대**, 꺼도 **1.8 / 4 대**다. 즉
**분리의 86% 를 판정 조건이 혼자 만든다.**

**두 메커니즘이 각자 같은 보호를 만들면, 하나씩 빼는 방식은 둘 다 0 으로 읽는다.** 둘을 같이
빼야 무너진다. 이 설계는 의도적으로 중복이 많으므로(격리를 게이트가 결과로 만들고, 선호가 그것을
강화하고, cap 이 상한을 씌운다) leave-one-out 이 **모든 요소를 구조적으로 과소평가한다.**

**그리고 회계가 안 맞는다.** 한 시간 trace 에서 FluidServe 78.7 대 llm-d 47.7 / 54.0 으로
**25~31 점** 차이인데, EXP-131·EXP-132 가 FluidServe 고유 메커니즘에 귀속시킨 것을 전부 더해도
**10 점이 안 된다.** 20 점 넘는 무언가가 고립되지 않았다.

## 2. 무엇을 벗기나 — 우리 것만, 공유하는 것은 건드리지 않는다

`related-works-review.md` §12.3 이 소스 대조로 정리한 **llm-d 와 남는 차이 여섯**을 기준으로
한다. **공유하는 것은 차별점이 아니므로 벗기지 않는다**: 인스턴스에 이미 있는 요청 중 가장
빡빡한 예산을 판정에 넣는 것(그들의 `running_request_tpot_slo_queue.go` 가 같은 값을 유지한다),
admission 으로 거절하는 것(`latency-slo-admitter`), prefix 선호
(`prefix-cache-affinity-filter`). 허용 속도 게이트의 여유 계수 0.90 도 벗기지 않는다 —
**그것은 파라미터이지 메커니즘이 아니다.**

| arm | 앞 단계에서 **하나** 더 뺀 것 | llm-d 와의 대응 |
|---|---|---|
| `cum0` | — (배포 설정 그대로) | |
| `cum1` | 클래스 선호 | 그들에게는 prefix 선호만 있다 |
| `cum2` | 보유(PEND) | §12.3 #6 — 도착 시 배치 아니면 거절 |
| `cum3` | 클래스별 인스턴스 상한 | 그들에게 없다 |
| `cum4` | KV flux 투영 | §12.3 #4 — KV 는 예측기의 입력 특징이지 제약이 아니다 |
| `cum5` | **도착 요청의 미래 디코드 선청구** (지평 1) | §12.3 #3 — `generatedTokenCounts[i] = 1` |

**`cum4` 는 `costOf` 를 건드리지 않는다** — `enableFlux` 는 `inflow` 와 `outflow` 만 0 으로
만든다(`fluidserve.go:1316`). 그래서 `cum5` 가 선청구를 깨끗하게 고립시킨다:
`costOf = promptTokens + min(horizonSteps, expectedToks)` 이므로 지평 1 은 프롬프트 + 1 토큰만
청구하고, 그것이 llm-d 예측기가 받는 것과 같다.

**각 arm 이 앞 arm 과 정확히 한 변수만 다른 것을 `set_arm` 을 불러 확인했다.**

## 3. `cum0` 은 대조군의 재측정이고, 그 자체가 유효성 검사다

`cum0` 은 배포 설정을 그대로 쓴다. **EXP-108 의 같은 셀(73.6~75.5, 2 반복) 안에 들어와야 하고,
안 들어오면 그 아래 단계를 하나도 읽을 수 없다** — 두 세션이 arm 말고 다른 것에서 다르다는
뜻이기 때문이다.

**이것은 EXP-108 과 중복이 아니다.** EXP-132 가 두 세션 사이에서 **preemption 이 2.1~2.6 배**
다른 것을 발견했고 원인을 찾지 못했다. `cum0` 은 **점수도 움직였는지**를 말해 주는 arm 이다.

## 4. 판정 규칙 — 실행 전에 정한다

조건당 **2 반복**, 정적 2100 rpm(35 req/s) 8 분, t75. 주 지표는 **모든 도착**, 옆에
admitted·거절률·goodput. 채점은 `FS_SWE_TBT_MS=75`(로더가 이제 강제한다).

| 차이 | 읽는 법 |
|---|---|
| \|Δ\| < 1.0 | 차이 없음 |
| 1.0 ≤ \|Δ\| < 3.0 | 판정하지 않는다 |
| \|Δ\| ≥ 3.0 | 실재하는 차이 |

**계단의 어느 칸에서 떨어지는지가 답이다.** 단계별 차이(`cum(n) − cum(n−1)`)를 그 요소의
**중복을 제거한 몫**으로 읽는다 — leave-one-out 값보다 클 것으로 예상하고, **그 둘의 차이가 곧
그 요소가 다른 요소와 얼마나 중복돼 있었는지**다.

### 4.1 사전 예측

- **`cum0` 은 73.6~75.5 안.** 벗어나면 아래를 읽지 않고 세션 차이부터 조사한다.
- **`cum1`(선호 제거)은 leave-one-out 과 같은 −3.3~−5.6** 이어야 한다. 첫 단계이므로 누적과
  leave-one-out 이 정의상 같다. **다르면 세션 효과이고 `cum0` 이 이미 그것을 말해 줄 것이다.**
- **`cum2`(보류) 와 `cum3`(cap) 은 leave-one-out 에서 0 이었다.** 누적에서도 0 이면 그
  요소들은 정말로 기여가 없는 것이고, 크면 **중복이 가려져 있었던 것**이다.
- **`cum4`(flux) 는 오히려 좋아질 것이다** — EXP-131 이 flux 를 끄면 정적에서 +5.5~+7.7
  좋아진다고 쟀다(`fsv3t75noflux` 81.3 / 81.0 대 대조군 73.6~75.5). 그러면 계단이 위로 꺾인다.
- **`cum5`(선청구 제거)가 가장 크게 떨어질 것이다.** EXP-131 의 지평 sweep 에서 h=1 이
  **34.5 / 35.0** 이었다. 다만 그때는 flux 가 켜져 있었으므로 같은 값이 나온다는 보장은 없다.

### 4.2 무엇이 이 실험을 반증하나

- **`cum5` 가 llm-d 의 47.7~54.0 근처로 내려오면** 25~31 점 차이가 이 메커니즘들로 설명된
  것이다.
- **안 내려오면**(예: `cum5` 가 여전히 70 점대) 남는 것은 **메커니즘 차이가 아니라 모델
  차이**다 — 우리는 프로파일에서 오프라인으로 적합한 해석적 step 시간 모델을 쓰고 그들은
  온라인으로 학습하는 예측기를 쓴다. **그 경우 논문은 그것을 함의로 두지 말고 그대로 적어야
  한다.**
- ⚠ **비교 대상이 다른 워크로드다.** llm-d 의 47.7 / 54.0 은 **한 시간 trace** 값이고 이 실험은
  **정적 35 req/s** 다. 계단의 절대값을 llm-d 의 한 시간 값과 직접 빼면 안 된다.
  llm-d 의 정적 35 req/s 값이 EXP-108 에 있으면 그것과 비교하고, 없으면 **계단의 모양만**
  읽고 llm-d 와의 비교는 한 시간에서 다시 한다.
